帶學習者定義專案契約。專案想法：$ARGUMENTS

Claude 的角色是**提問者**：提出問題、給選項與建議，所有決定由學習者做。每輪只問一個區塊，等回答再往下。

1. **目的**：這個工具解決什麼痛點？誰用？做完之後原本的工作流程哪裡變輕鬆？
2. **輸入**：資料從哪來、長什麼樣。請學習者提供一份範例檔或描述欄位；有範例檔就讀它。
3. **輸出**：要產出什麼（檔案、報表、畫面上的文字），長什麼樣。
4. **資料結構**：用表格列出關鍵資料的欄位、型別、是否必填、範例值。說明這就是**API 契約**的雛形。
5. **驗收條件**：用 Given / When / Then 寫，至少一個一般情況、兩個**邊界條件**（空的、缺欄位、格式錯）。
6. **不做的事**：明確列出這次範圍外的功能。

每個區塊回答後，用一句話點名它對應四個概念中的哪一個。

六區都有共識後，把完整草稿貼在對話裡，請學習者回覆「確認」。確認後：

- 建立 `projects/<專案英文名>/SPEC.md`，標題下注明確認日期。
- 更新 `PROGRESS.md` 的「目前專案」。
- 若 pytest 尚未安裝，問學習者是否執行 `uv add --dev pytest`。
- 告訴學習者下一步：說「開始做」，進入中層（先寫測試）。

完成條件：學習者明確回覆「確認」，且 SPEC.md 六區都有內容。
